# Benchmark v1: со скиллом против без скилла

Первая проверка скилла `designing-ai-infra`: помогает ли он агенту отвечать на
вопросы об инфраструктуре ИИ лучше, чем та же модель без скилла.

## Метод

35 сценариев набора `evals/benchmark-v1.json`, размер зафиксирован до прогона:
22 свободных ответа, 5 заполненных артефактов по шаблонам и 8 расчётов с
известным числовым ответом. По одному прогону на конфигурацию, 70 ответов,
все прогоны и оценки выполнены моделью opus 2026-09-28.

- **Со скиллом.** Агент читал `SKILL.md` из снимка скилла на коммите `eb8b3a4`
  (без каталога `evals`) и следовал его маршрутизации.
- **Без скилла.** Тот же промпт без пути к скиллу и с указанием открывать
  только приложенные данные.

Приложенные данные в обоих случаях копировались в нейтральный каталог вне
плагина, чтобы пути в промпте не вели к скиллу и эталонам расчётов.

Оценка парная, без указания конфигурации: оценщик получал ответы как A и B,
по четыре пары на вызов. Раскладка задавалась хешем идентификатора сценария:
A = со скиллом при `sha256(id) % 2 == 0` (17 сценариев из 35). Ярлыки скрыты,
но ответ со скиллом узнаётся по содержанию (см. «Ограничения»), поэтому
слепота формальная. Промпт оценщика тот же, что в benchmark v4 скилла для
агентов: критерий засчитывается только при явном выполнении, длина ответа
достоинством не считается, по каждому критерию отдельный вердикт для A и B,
победитель и причина одной строкой. Добавлено одно требование: читать
приложенные данные и сверять числа. Оценка до замера засчитывалась при любой
явной формулировке.

Для 8 расчётных сценариев итоговое число из каждого ответа отдельно сверено с
`evals/calc-goldens.json` (относительный допуск 1 %).

Статистика:

- `scripts/eval_stats.py compare` на 146 парных исходах критериев
  (A = со скиллом); результат совпал с отдельной сводкой по тем же оценкам;
- знаковый тест по сценариям: в скольких сценариях у одной конфигурации
  выполнено больше критериев, чем у другой;
- биномиальный тест побед в парном сравнении.

Оба теста по сценариям посчитаны через `binomial_two_sided` из того же
`eval_stats.py`.

## Результат

| Метрика | Со скиллом | Без скилла |
|---|---:|---:|
| Критериев выполнено | 135/146 (92,5 %) | 81/146 (55,5 %) |
| Сценариев, где критериев больше | 25 | 0 |
| Побед в парном сравнении | 29 | 0 |
| Итоговое число в допуске (расчёты) | 8/8 | 8/8 |

Расхождения по критериям: со скиллом лучше в 57 случаях, без скилла — в 3.
Точный тест McNemar: p = 6,3·10⁻¹⁴.

Знаковый тест по сценариям: 25 против 0 при 10 равных, p = 6,0·10⁻⁸. Этот
тест не зависит ни от независимости критериев внутри сценария, ни от суждения
оценщика «кто лучше» и поэтому служит основной проверкой значимости.

Побед в парном сравнении 29 против 0 при 6 ничьих, p = 3,7·10⁻⁹. Четыре из
этих побед приходятся на сценарии с равным счётом по критериям (113, 117, 120,
304); без них 25 против 0, p тот же, 6,0·10⁻⁸.

По видам сценариев:

| Вид | Со скиллом | Без скилла | Расхождения, McNemar p | Сценариев больше : меньше : равно, p | Победы |
|---|---:|---:|---|---|---|
| Свободный ответ (22) | 88/97 (90,7 %) | 59/97 (60,8 %) | 32 : 3, p = 4,2·10⁻⁷ | 16 : 0 : 6, p = 3,1·10⁻⁵ | 19 : 0, ничьих 3 |
| Артефакт (5) | 23/25 (92,0 %) | 2/25 (8,0 %) | 21 : 0, p = 9,5·10⁻⁷ | 5 : 0 : 0, p = 0,0625 | 5 : 0 |
| Расчёт (8) | 24/24 (100 %) | 20/24 (83,3 %) | 4 : 0, p = 0,125 | 4 : 0 : 4, p = 0,125 | 5 : 0, ничьих 3 |

На уровне сценариев значимость есть только для всего набора и для свободных
ответов. У артефактов 5 : 0 дают p = 0,0625, это минимум, возможный при пяти
сценариях; значимость по артефактам держится только на допущении о
независимости критериев. На расчётных сценариях разница не значима ни по
критериям, ни по сценариям.

### Где скилл не помог

Шесть ничьих в парном сравнении: 103 `moe-int4-on-rtx4090` (5/5 и 5/5),
105 `ttft-spike-at-peak` (3/5 и 3/5), 110 `double-gpus-and-batch` (4/4 и 4/4),
303 `calc-qwen3-30b-a3b-h200-decode-batch4`,
307 `calc-cost-per-successful-task-retry-tree` и
308 `calc-computer-use-cloud-task-time` (все три 3/3 и 3/3). Ещё в четырёх
сценариях счёт по критериям равный, а победа отдана ответу со скиллом за то,
что критериями не покрыто: 113, 117, 120, 304. Эти четыре победы сильнее
других зависят от узнаваемости ответа и от его длины.

Три критерия, где ответ без скилла выполнил требование, а ответ со скиллом нет:

- **105, критерий 2:** загрузка по 30-секундным окнам пика. Ответ со скиллом
  посчитал интенсивность в окне (6,8–7,1 запроса/s) и потребность prefill на
  карту (46 920 входных токенов/s), но не сравнил её с наблюдаемыми
  ≈ 24 тыс./s.
- **105, критерий 4 (вердикт спорный, против скилла):** всплески ITL
  300–400 ms. Оба ответа объясняют их prefill длинных запросов при
  `chunked_prefill=false` и называют рычагом блочный prefill; ответ без скилла
  добавляет только конкретный `max_num_batched_tokens` 4–8k.
- **111, критерий 5:** асинхронный режим или перекрытие этапов с оговоркой об
  устаревших версиях стратегии. В ответе со скиллом асинхронного режима нет:
  из перекрытия этапов предложена только проверка во время генерации, без
  оговорки об устаревании стратегии. Ответ без скилла описывает асинхронную
  схему с отставанием на один шаг и поправкой на устаревание.

Ответ со скиллом не выполнил 11 критериев. Кроме трёх названных, это 101/2,
102/3, 106/2, 107/4, 113/4, 117/3, 204/4 и 205/2; их не выполнил и ответ без
скилла.

### Спорные вердикты

Вердикты первого оценщика вне 201–205 не переоценивались. Выборочная
перепроверка при ревью нашла три спорных вердикта в обе стороны: 101/1 и
119/4 не в пользу ответа без скилла, 105/4 не в пользу ответа со скиллом.
Данные оценки не менялись. Если засчитать 101/1 и 119/4 ответу без скилла,
счёт становится 135 против 83 при расхождениях 55 : 3 (McNemar
p = 2,3·10⁻¹³); если ещё и 105/4 засчитать ответу со скиллом — 136 против 83
при 55 : 2 (p = 2,3·10⁻¹⁴). В первом варианте знаковый тест по сценариям не
меняется (в 101 и 119 остаётся 4 против 2), во втором 105 переходит из
равных в перевес со скиллом (26 : 0). Направление результата не меняется.

### Расчётные сценарии

Итоговое число в допуске 1 % у обеих конфигураций во всех 8 сценариях.
Промпты расчётных сценариев фиксируют все соглашения (пики железа, резервы
памяти, правила подсчёта FLOPs), поэтому по итоговым числам этот набор
конфигурации не различает. Четыре расхождения по критериям касаются
рассуждения, а не числа: названа ли оценка верхней границей (301), показан ли
вклад внимания в FLOPs prefill (302), отмечена ли точка восстановления как
последний зафиксированный снимок (305), названо ли MFU 40 % допущением с
нижней границей при MFU 1 (306).

### Проверка чувствительности

Критерии артефактных сценариев составные, а строгое правило засчитывает
критерий только целиком. Чтобы проверить, насколько это завышает разрыв,
второй независимый оценщик (opus, та же раскладка A/B) заново оценил
сценарии 201–205 строго и поэлементно по требованиям внутри каждого критерия.

| Оценка 201–205 | Со скиллом | Без скилла |
|---|---:|---:|
| Строгая, первый оценщик | 23/25 (92 %) | 2/25 (8 %) |
| Строгая, второй оценщик | 22/25 (88 %) | 3/25 (12 %) |
| Поэлементная, второй оценщик | 115/120 (95,8 %) | 73/120 (60,8 %) |
| Победы, второй оценщик | 5 | 0 |

Оценщики совпали в 48 вердиктах из 50. Расхождения: 204, критерий 2 со
скиллом (первый засчитал, второй нет) и 205, критерий 4 без скилла (наоборот).
Ответ без скилла на артефактах выполняет большую часть отдельных требований,
но почти ни один критерий целиком. Направление разницы при поэлементном счёте
сохраняется, её размер меньше.

## Вывод

**На этих 35 сценариях ответы opus со скиллом лучше, чем ответы opus без
скилла.** Разница по критериям (92,5 % против 55,5 %) значима, и её
подтверждает знаковый тест по сценариям (25 против 0, p = 6,0·10⁻⁸). На
уровне сценариев значимость есть для всего набора и для свободных ответов;
на артефактах разрыв большой, но сценариев пять, а строгий счёт его завышает:
при поэлементном счёте остаётся 96 % против 61 %.

На расчётных сценариях заявленная в спецификации цель — заметно более высокая
доля чисел в допуске — **не подтверждена**: 8/8 у обеих конфигураций. Скилл
выполнил там больше критериев рассуждения (24/24 против 20/24), но на 8
сценариях это не значимо (p = 0,125).

Перенос результата на другие модели и на независимые наборы сценариев не
проверялся.

## Ограничения

- Один прогон на конфигурацию: разброс самих прогонов не измерен.
- Ответы писала и оценивала одна семья моделей (opus), и проверена только она.
- Слепота формальная. Ответ со скиллом узнаётся в каждой паре: ссылки
  `references/source-book/...` есть в 35 ответах со скиллом из 35 и ни в одном
  без скилла, раздел «Evidence / inference / unknown» — 35 и 0, команды
  `calc.py` — 33 и 0, упоминание каталога скилла — 18 и 0. Сильнее всего это
  влияет на победы в парном сравнении, особенно на четыре победы при равном
  счёте; меньше — на критерии, которые засчитываются только при явном
  выполнении, и на знаковый тест по ним.
- Критерии артефактов составные, и строгое правило завышает разрыв на них:
  92 % против 8 % строго, 96 % против 61 % поэлементно у второго оценщика.
  Согласие двух оценщиков на строгой оценке — 48 из 50 вердиктов.
- Промпты расчётных сценариев фиксируют все соглашения, поэтому итоговые числа
  8/8 в обеих конфигурациях; выигрыш на расчётах только в критериях
  рассуждения, не в итоговых числах.
- Сценарии и критерии написаны в том же проекте, что и скилл, поэтому
  покрытие сценариев скиллом задано замыслом, а не проверено на независимом
  наборе.
- Конфигурации без скилла было указано открывать только приложенные данные;
  как она ответила бы с доступом к другим материалам, не проверялось. У
  конфигурации со скиллом такого ограничения не было. По тексту самих
  ответов 9 из них взяли `config.json` с Hugging Face (102, 105, 106, 107,
  109, 112, 113, 114, 115), ещё 2 сверили с ним приложенный конфиг (204, 301),
  3 прямо пишут, что не скачивали и не сверяли (103, 121, 202). Доступ к
  внешним данным у конфигураций неравный; повлияло ли это на оценки,
  неизвестно.
- McNemar считает 146 критериев независимыми, хотя критерии одного сценария
  оценивают один и тот же ответ. Знаковый тест по сценариям этой зависимости
  не имеет и тоже значим для всего набора.
- Ответ со скиллом длиннее ответа без скилла во всех 35 сценариях (в среднем
  около 1200 слов против 830 по грубому счёту). Оценщику было указано не
  считать длину достоинством, но у длинного ответа больше места явно выполнить
  критерий. Против того, что разрыв объясняется длиной, говорят две вещи:
  - связь отношения длин с разрывом по критериям слабая и отрицательная
    (Спирмен −0,17 для разрыва в доле критериев);
  - расчётные ответы со скиллом длиннее в 1,9–3,5 раза, а итоговые числа
    совпадают, и 3 из 8 расчётных сценариев — ничьи.

  Четыре победы при равном счёте — там, где длина могла повлиять. Лимит слов
  из промпта ответ со скиллом превысил в 101 (953 при лимите 900) и 104 (919
  при лимите 800), ответ без скилла — только в 101 (906). Расход токенов и
  время прогонов в собранных данных не записаны.
