# Designing AI Infra

Плагин для Claude Code и Codex с одним скиллом, который помогает считать,
проектировать и диагностировать инфраструктуру для инференса и обучения LLM.
Скилл опирается на книгу Bojie Li «AI Infra in Depth: Quantitative Analysis and
System Design» («AI-инфраструктура изнутри») — её русский текст входит в
плагин.

Скилл пригодится, если нужно:

- посчитать, сколько GPU нужно под модель, нагрузку и требования к задержке;
- понять, почему время до первого токена или между токенами хуже ожидаемого;
- сравнить модели по памяти и цене: варианты внимания (GQA, MLA), модели с
  экспертами (MoE);
- спроектировать распределённый инференс или кластер для обучения;
- выбрать ускорители, топологию и сеть;
- оценить стоимость токена и задачи агента — на своих GPU или через API;
- спланировать пул ресурсов под агентов и RL;
- решить, где запускать модель: на устройстве, на периферии или в облаке.

Для сети, базы данных или веб-приложения без моделей он не нужен.

## Как пользоваться

Опишите задачу обычным текстом — скилл подключится сам. Например:

```text
Сколько H100 нужно, чтобы держать Qwen3-32B на 200 одновременных сессий с контекстом 16k и TTFT до 1 с?
vLLM на A100: при 20 параллельных запросах TTFT вырос с 400 мс до 9 с, загрузка GPU около 60 %. Куда смотреть?
Что выгоднее при контексте 200k: модель с MLA или с GQA? Посчитай KV на пользователя.
Полное дообучение 70B на 5 млрд токенов: сколько GPU, сколько недель и какой stage ZeRO?
Обучение на 1000 GPU падает раз в шесть часов, checkpoint пишется 20 минут. Как часто сохраняться?
Задача агента — 12 вызовов модели, контекст растёт до 40k, 70 % задач решаются с первой попытки. Сколько стоит решённая задача на своих H100 и через API?
```

Вызвать явно тоже можно: в Claude Code —
`/designing-ai-infra:designing-ai-infra <задача>`, в Codex —
`Используй $designing-ai-infra, чтобы <задача>`.

Назовите модель — скилл скачает её `config.json` с Hugging Face; если сети
нет или модель закрытая, приложите файл сами. Встроенных цен нет: для расчёта
стоимости укажите цену GPU-часа или токенов.

## Что вы получите

- **Сначала решение**, потом расчёт.
- **Числа с командами калькулятора.** Каждое число, от которого зависит
  решение, считает `scripts/calc.py`; в ответе есть команда и её вывод — их
  можно перепроверить.
- **Порог вместо «A лучше B»**: при какой нагрузке, длине контекста или цене
  решение меняется.
- **Узкое место**: что ограничивает — вычисления, чтение памяти, сеть или
  очередь.
- **Факты отдельно от оценок.** Расчёт — это нижняя граница или оценка до
  замера; скилл говорит, что нужно измерить, чтобы подтвердить вывод.
- **Риски**: хвосты задержек, всплески нагрузки, сбои, устаревание цен и
  железа.
- **Документ по шаблону**, если попросите: расчёт мощностей, диагностика
  узкого места, решение о развёртывании, план обучения, план пула ресурсов.
- **Ссылки на книгу** со строками.

При разборе проблем скилл ничего не меняет сам: не правит конфиги, не
перезапускает сервисы и не запускает нагрузочные тесты без вашей просьбы.

## Калькулятор

Калькулятор можно запускать и самому. Нужен Python 3.10 или новее, сторонние
пакеты не нужны. Склонируйте репозиторий:

```bash
git clone https://github.com/ilkruglov/designing-ai-infra-skill
```

Команды запускаются из каталога
`plugins/designing-ai-infra/skills/designing-ai-infra`. Каждый результат
выводится с формулой, входными данными и ссылкой на строку книги,
`--help` показывает все команды.

```bash
# 80 GB на этикетке — это 74,5 GiB
python3 scripts/calc.py units --size '80 GB' --to GiB

# веса, KV на токен и FLOPs для модели при входе 4096 токенов
python3 scripts/calc.py model --config scripts/tests/fixtures/configs/qwen3-8b.json --context 4096

# с какого batch чтение KV догоняет чтение весов (пример 2-2 книги: 13 при 8192)
python3 scripts/calc.py batch-threshold --config scripts/tests/fixtures/configs/qwen3-8b.json --context 8192 --device h100-sxm

# оптимальный период checkpoint для 768 GPU
python3 scripts/calc.py checkpoint --checkpoint-bytes 2e11 --save-bandwidth 1e10 --devices 768 --device-mtbf 2.5e7 --recovery 300

# стоимость вызова и решённой задачи с кэшем префикса и повторным запуском неудачных задач (успех 70 %)
python3 scripts/calc.py cost --input-tokens 5000 --cached-tokens 18000 --output-tokens 700 --input-price 0.8 --cache-read-price 0.08 --output-price 3.2 --calls 12 --success 0.7
```

Конфиги в `scripts/tests/fixtures/configs/` — тестовые; для своей модели
передайте её `config.json`. Характеристики ускорителей взяты из снимка
каталога автора книги (`data/hardware.json`), дата снимка печатается в выводе.
Значения снимка можно заменить флагами `--memory`, `--bandwidth` и
`--peak-tflops`. Сам скилл перед решением сверяет цены и железо с первичными
источниками и указывает дату.

## Ограничения

- Калькулятор не моделирует эффективность ядер, фрагментацию памяти,
  перегрузку сети и хвосты задержек; скилл называет, что измерить.
- Незнакомую архитектуру калькулятор не считает как плотную: он отказывается и
  перечисляет поля конфига, которые не поддерживает, а скилл помечает такой
  расчёт как неизвестный.

## Насколько это помогает

На 35 задачах на расчёт мощностей, диагностику и планирование ответы со
скиллом выполнили 92,5 % критериев против 55,5 % без него. В 25 задачах ответ
со скиллом набрал больше критериев, в 10 — столько же, меньше — ни в одной.
Разница в разборе: итоговые числа в восьми расчётных задачах сошлись с
эталоном у обеих конфигураций.

Ограничения замера: один прогон; ответы писала и оценивала одна модель
(opus); оценщик мог узнать ответ со скиллом по ссылкам на книгу и командам
калькулятора; ответы со скиллом длиннее (около 1200 слов против 830);
конфигурации без скилла разрешалось открывать только приложенные данные, а со
скиллом — в том числе Hugging Face; задачи и критерии написаны в этом же
проекте. Замер сделан на предварительной сборке версии 0.1.0. Метод и разбор —
в [`benchmarks/v1/benchmark.md`](plugins/designing-ai-infra/benchmarks/v1/benchmark.md).

В замере срабатывания на версии 0.1.0 в Claude Code скилл сработал на 18 из
18 запросов про инфраструктуру и ни на одном из 19 посторонних, в том числе на
7 вопросах об устройстве агента. Это результат одного прогона: посторонний
запрос про сеть дата-центра для Postgres и Kafka в повторных запусках вызывал
скилл в 6 из 11 случаев. Для версий 0.1.1 и 0.1.2 замер срабатывания не
повторялся.

## Соседний скилл

Устройство самого агента — промпты, инструменты, память, контекст, оценка
качества — относится к скиллу
[`developing-ai-agents`](https://github.com/ilkruglov/developing-ai-agents-skill).
Здесь — инфраструктура под агентом: сколько GPU нужно под его нагрузку, сколько
памяти KV занимает растущий контекст агента, сколько стоит задача на железе или
через API. Оба скилла можно установить вместе.

## Для разработчиков

```bash
python3 scripts/validate.py
python3 -m unittest discover -s tests
python3 -m unittest discover -s plugins/designing-ai-infra/skills/designing-ai-infra/scripts -t plugins/designing-ai-infra/skills/designing-ai-infra/scripts
claude plugin validate . --strict
```

`scripts/validate.py` проверяет, что цитаты из книги дословны, ссылки на
строки не сдвинулись, текст книги и снимок железа не изменены, а у каждой
функции калькулятора есть тест с эталоном из книги или расчётов автора.
Тесты в `tests/` запускают каждую команду калькулятора из документации. После
намеренной правки ссылок на книгу обновите фиксацию якорей:
`python3 scripts/build_source_lock.py`.
